## 2. API Contract Specification (REST)

All API endpoints follow strict RESTful conventions under `/api/v1/`.

| Endpoint | Method | Role | Description |
|---|---|---|---|
| `/api/v1/health` | `GET` | Public | System status and crate version check |
| `/api/v1/auth/login` | `POST` | Public | Authenticate operator, return JWT with tenant claims |
| `/api/v1/payments/evaluate` | `POST` | Operator/System | Submit payment context for agent risk evaluation |
| `/api/v1/payments/execute` | `POST` | Payment Service | Execute money-moving PayPal capture (Policy ALLOW required) |
| `/api/v1/payments/{id}` | `GET` | Operator | Retrieve payment record and state machine history |
| `/api/v1/decisions/{id}` | `GET` | Operator | Retrieve policy outcome, reasons, and supporting findings |
| `/api/v1/agents` | `GET` | Operator | List all 13 agents, versions, and capability descriptors |
| `/api/v1/agents/{id}/invoke`| `POST` | Internal/Operator | Directly invoke single agent for sandbox diagnostics |
| `/api/v1/audit/events` | `GET` | Compliance | Paginated query of immutable audit log with filters |

## 3. Database Architecture & ER Design

### Table Layout
1. **`tenants`**: Tenant registry with rate limits, billing tier, and activation flags.
2. **`users`**: Platform operators and merchant accounts with Argon2-hashed passwords and RBAC roles.
3. **`transactions`**: Inbound payment requests with `amount`, `currency`, status (`PaymentStatus`), and correlation trace ID.
4. **`policy_rules`**: Versioned deterministic predicates (e.g. `VELOCITY_CHECK`, `DEVICE_COMPROMISE_FLAG`).
5. **`policy_decisions`**: Persisted decisions (`ALLOW`, `DENY`, `STEP_UP`, `MANUAL_REVIEW`) linked to transactions.
6. **`agent_findings`**: Structured findings generated by the 13 agents with evidence references.
7. **`audit_events`**: Append-only log of all security, authentication, and financial transitions.
8. **`idempotency_keys`**: Request locking and deduplication store with 24-hour TTL.

## 4. Threat Model & Trust Boundaries (STRIDE)

| Threat Category | Target | Mitigations |
|---|---|---|
| **Spoofing** | Tenant Identity | JWT with HMAC-SHA256 signature; tenant ID extracted strictly from verified token, never request body. |
| **Tampering** | Agent Findings | In-memory message validation; findings signed with hash; agents cannot mutate DB tables directly. |
| **Repudiation** | Financial Decisions | Immutable audit events logged synchronously before and after policy decisions. |
| **Information Disclosure** | PII / Credentials | Full card PAN, CVVs, and PayPal secrets never persisted or logged; passwords salted with Argon2id. |
| **Denial of Service** | Agent LLM Latency | Hard Tokio timeouts per agent (default 500ms); circuit breakers fall back to deterministic `MANUAL_REVIEW`. |
| **Elevation of Privilege** | Agent Autonomy | Policy engine is pure Rust with zero LLM bypass; only dedicated `payment-paypal` service can trigger capture. |
